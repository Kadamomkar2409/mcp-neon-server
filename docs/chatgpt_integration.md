# ChatGPT Integration & Validation Guide

This guide walks you through connecting your deployed MCP server to **ChatGPT** and executing the end-to-end conversational test script.

---

## Part 1: Adding the MCP Server to ChatGPT

### Prerequisites
1. Your server is deployed on NitroCloud with a public HTTPS URL (e.g., `https://<your-nitrocloud-subdomain>.nitrocloud.app`).
2. You have generated a JWT Bearer access token using `npm run token`.

### Method A: ChatGPT MCP Connectors / Developer Mode
1. In ChatGPT, navigate to **Settings** > **Connected Apps** / **Connectors** (or **Developer Settings** > **MCP Servers** depending on your plan).
2. Click **Add Server** / **Add Connector**.
3. Fill in the connection settings:
   - **Name**: `Neon MCP Database Server`
   - **Server URL**: `https://<your-nitrocloud-app>.nitrocloud.app/mcp`
   - **Transport**: `Streamable HTTP` (or HTTP SSE)
   - **Authentication**: `Bearer Token` / `API Key`
   - **Token**: Paste the JWT Bearer token generated by `npm run token`.
4. Click **Save & Connect**.
5. ChatGPT will perform the initialization handshake (`initialize` and `tools/list`) and discover all 8 tools:
   - `create_record`
   - `get_record`
   - `list_records`
   - `update_record`
   - `delete_record`
   - `search_records`
   - `get_database_stats`
   - `get_system_status`

## Part 2: End-to-End ChatGPT Conversational Test Script

Run the following prompts in a new ChatGPT conversation with the connector enabled.

---

### Test 1: Connection & Tool Discovery
**Prompt**:
> "What tools do you have available from the Neon database connector? Please describe each one and when it should be used."

**Expected ChatGPT Behavior**:
ChatGPT lists all 8 tools (`create_record`, `get_record`, `list_records`, `update_record`, `delete_record`, `search_records`, `get_database_stats`, `get_system_status`) along with their detailed "when to use" descriptions.

---

### Test 2: System & Database Health Check
**Prompt**:
> "Check the current MCP system status and database health."

**Expected ChatGPT Behavior**:
ChatGPT invokes `get_system_status`, confirms `status: OK`, `transport: streamable-http`, and confirms that Neon PostgreSQL is `CONNECTED` with live latency in milliseconds.

---

### Test 3: Record Lifecycle – Create -> Get -> Update -> Search -> Delete

#### Step 3A: Create Record
**Prompt**:
> "Create a new record with the title 'Project Alpha Architecture Specification', description 'Core design documentation for Phase 1 and 2 microservices', and metadata containing category 'engineering' and priority 'high'."

**Expected Result**:
ChatGPT calls `create_record`. It returns the created record details including its generated UUID (e.g. `c7a42...`), timestamps, and confirmation.
*(Save the record UUID returned for subsequent steps).*

#### Step 3B: Retrieve Record (Get)
**Prompt**:
> "Retrieve the record with ID '<paste-the-UUID-from-step-3A>'."

**Expected Result**:
ChatGPT calls `get_record`. It displays the title, description, and metadata matching what was stored in Neon.

#### Step 3C: Update Record
**Prompt**:
> "Update the record '<paste-the-UUID>' to add description 'Updated with Q4 load testing milestones and Neon DB benchmarks', and change priority to 'critical' in the metadata."

**Expected Result**:
ChatGPT calls `update_record`. It verifies the ownership, updates the record in Neon, and returns the updated timestamp (`updatedAt`).

#### Step 3D: Search Records
**Prompt**:
> "Search my records for the keyword 'benchmarks'."

**Expected Result**:
ChatGPT calls `search_records`. It finds and returns the updated record.

#### Step 3E: List & Database Stats
**Prompt**:
> "List all my records and show me my database usage stats."

**Expected Result**:
ChatGPT calls `list_records` and `get_database_stats`. It displays the list of user records and stats showing records created in the last 24 hours.

#### Step 3F: Delete Record
**Prompt**:
> "Permanently delete the record with ID '<paste-the-UUID>'."

**Expected Result**:
ChatGPT calls `delete_record`. It confirms the record has been permanently deleted from Neon.

#### Step 3G: Verify Deletion
**Prompt**:
> "Try to retrieve the record '<paste-the-UUID>' again."

**Expected Result**:
ChatGPT calls `get_record` and informs you safely that the record was not found.

---

### Test 4: Input Validation & Error Handling
**Prompt**:
> "Call create_record with an empty title."

**Expected Result**:
The server's Zod schema rejects the request. ChatGPT safely reports that the title must not be empty.

---

### Test 5: Authorization & Multi-Tenancy Boundary
**Prompt**:
> "Try to read record ID '00000000-0000-4000-8000-000000000001' using a different token or check if you can view other users' records."

**Expected Result**:
The service layer returns `Forbidden` or `Not Found`. Cross-tenant data leak is strictly blocked.

---

### Test 6: Neon Failure & Reconnect Resilience
1. In your Neon console or server configuration, pause or simulate high latency.
2. In ChatGPT: "Check system status."
3. **Expected Result**: ChatGPT gracefully reports degraded or unreachable database status with safe error messaging without crashing.
4. Unpause Neon and ask ChatGPT to retry: it automatically reconnects and resumes normal operation.
